-- CONTEXTO --
Se desea informatizar la gestión integral de turnos y atención médica del centro polivalente "SaludVida".
La institución cuenta con un cuerpo de médicos especialistas, un registro de pacientes y un cronograma diario de turnos médicos asignados.

============================================================
1. MODELO ENTIDAD-RELACIÓN (MER)
============================================================
A partir de los siguientes requerimientos, diseñe el Modelo Entidad-Relación correspondiente:

- Un PACIENTE puede solicitar y tener asignados varios turnos a lo largo del tiempo, pero cada turno pertenece a un único paciente específico (Relación 1 a N).
- Un MÉDICO atiende numerosos turnos en su consultorio, pero cada turno en una fecha y hora determinada es atendido por un único profesional médico (Relación 1 a N).
- Debe identificar claramente en su diagrama: Entidades, Atributos, Claves Primarias (PK), Claves Foráneas (FK) y Cardinalidades.

============================================================
2. DEFINICIÓN Y ESTRUCTURA CON CLAVES FORÁNEAS (DDL)
============================================================
Implemente la estructura física de la base de datos escribiendo las sentencias SQL correspondientes:

1. Creación de la base de datos:
   Cree una nueva base de datos llamada 'saludvida'.
   [CREATE DATABASE]

2. Selección de la base de datos:
   Active y comience a trabajar sobre la base de datos 'saludvida'.
   [USE]

3. Creación de tablas principales:
   Cree las siguientes tablas definiendo atributos, tipos y relaciones:

   • Tabla: medicos
     - idMedico: INT, PRIMARY KEY
     - nombre: VARCHAR(50), NOT NULL
     - apellido: VARCHAR(50), NOT NULL
     - especialidad: VARCHAR(50), NOT NULL
     - matricula: VARCHAR(20), NOT NULL
     - consultorio: INT, NOT NULL
     [PRIMARY KEY]

   • Tabla: pacientes
     - idPaciente: INT, PRIMARY KEY
     - nombre: VARCHAR(50), NOT NULL
     - apellido: VARCHAR(50), NOT NULL
     - anio_nacimiento: INT, NOT NULL
     - obra_social: VARCHAR(50) (permite valores nulos en pacientes particulares)
     - telefono: VARCHAR(30)
     [PRIMARY KEY]

   • Tabla: turnos
     - idTurno: INT, PRIMARY KEY
     - idPaciente: INT, NOT NULL (Clave foránea referenciando a pacientes)
     - idMedico: INT, NOT NULL (Clave foránea referenciando a medicos)
     - fecha: DATE, NOT NULL
     - hora: TIME, NOT NULL
     - motivo_consulta: VARCHAR(150), NOT NULL
     - estado: VARCHAR(20), NOT NULL
     [FOREIGN KEY ... REFERENCES]

4. Modificaciones sobre tablas existentes:
   - Agregar columna: Incorpore el campo 'observaciones' de tipo texto (VARCHAR(200)) en la tabla 'turnos'.
     [ADD]
   - Renombrar columna: En la tabla 'pacientes', cambie el nombre del atributo 'telefono' por 'celular' (manteniendo VARCHAR(30)).
     [RENAME COLUMN] o [CHANGE]
   - Eliminar columna: Elimine la columna 'observaciones' recientemente agregada en la tabla 'turnos'.
     [DROP COLUMN]

4. CONSULTAS BÁSICAS DE DATOS (DQL)
============================================================
* IMPORTANTE: Resuelva cada consigna con una consulta SQL simple sobre una sola tabla.
* NO debe utilizar JOINs ni subconsultas.
* Cada ejercicio cuenta con una palabra clave, símbolo o función guía entre corchetes:

1. Agrupamiento de registros:
   Calcule cuántos profesionales médicos atienden por cada especialidad médica disponible.
   [GROUP BY]

2. Filtro sobre grupos agregados:
   Muestre únicamente las especialidades médicas que tengan 2 o más profesionales registrados.
   [HAVING]

3. Conteo por estados de servicio:
   Cuente cuántos turnos existen registrados en la tabla 'turnos' discriminados por cada estado ('Atendido', 'Pendiente', 'Cancelado').
   [GROUP BY]

4. Búsqueda de valores ausentes (Nulos):
   Liste todos los pacientes particulares que NO tengan ninguna obra social registrada.
   [IS NULL]

5. Búsqueda de valores presentes (No nulos):
   Liste el nombre, apellido y obra social de todos los pacientes que SÍ cuentan con cobertura médica registrada.
   [IS NOT NULL]

6. Filtrado en rango de fechas:
   Liste todos los turnos programados cuya fecha se encuentre comprendida entre el '2024-05-01' y el '2024-05-15'.
   [BETWEEN]

7. Coincidencia por patrón de texto:
   Busque a los médicos cuya especialidad finalice con el sufijo 'logía'.
   [LIKE]

8. Ordenamiento cronológico:
   Muestre los turnos en estado 'Pendiente' ordenados de forma ascendente según fecha y hora de atención.
   [ORDER BY ASC]

9. Conteo puntual con filtro:
   Calcule la cantidad total de turnos registrados para el profesional con idMedico = 1.
   [COUNT]

10. Cálculo de promedio:
    Obtenga el año de nacimiento promedio de todos los pacientes registrados en el sistema.
    [AVG]

5. MODIFICACIÓN Y ELIMINACIÓN DE REGISTROS (DML)
============================================================
Escriba las sentencias SQL necesarias para actualizar o dar de baja información en la base de datos:

1. Actualización puntual:
   Modifique el turno con idTurno = 21 actualizando su hora a '16:30:00' y su estado a 'Atendido'.
   [UPDATE]

2. Reasignación condicional masiva:
   Por licencia médica del profesional, reasigne todos los turnos del médico con idMedico = 2 para que pasen a estar a cargo del profesional con idMedico = 5.
   [SET]

3. Eliminación puntual de turno:
   Elimine de la tabla 'turnos' el registro correspondiente al idTurno = 30 tras confirmación de ausencia.
   [DELETE]

4. Eliminación condicional por criterio:
   Elimine definitivamente de la tabla 'turnos' a todas las citas médicas que hayan quedado en estado 'Cancelado'.
   [WHERE]
